# 🤖 n8n Slack AI Recipe Assistant

An event-driven **AI automation workflow built with n8n, Slack, OpenAI, and JavaScript**.

This project listens for a new message posted in a Slack channel, extracts the user's recipe/food request, sends it to an LLM to generate a practical list of required ingredients and products, cleans the AI response using JavaScript, and finally posts the generated response back into Slack.

---

## 📌 Project Overview

The **n8n Slack AI Recipe Assistant** demonstrates how a traditional Slack messaging workflow can be enhanced with Generative AI.

A user can simply send a recipe name such as:

```text
Chicken Biryani
```

The workflow automatically:

1. Receives the new Slack message.
2. Checks whether the message was generated by a bot.
3. Extracts the recipe name from the Slack event payload.
4. Sends the recipe name to an OpenAI-powered LLM.
5. Generates a practical ingredient/product list.
6. Cleans the LLM response using JavaScript.
7. Sends the final response back to the Slack channel.

# 🔄 End-to-End Workflow

## 1. Slack User Message

The process starts when a user posts a message in the configured Slack channel.

Example:

```text
Chicken Biryani
```

The Slack Trigger is configured to listen for the `message` event and uses the configured Slack channel.

---

## 2. Slack Trigger

### Node

```text
Slack Trigger
```

### Purpose

The Slack Trigger acts as the event-driven entry point of the automation.

It listens for a new message posted to the configured Slack channel.

Conceptually:

```text
Slack Message
      ↓
Slack Event
      ↓
n8n Slack Trigger
```

The incoming Slack payload contains information such as:

```json
{
  "type": "message",
  "user": "USER_ID",
  "text": "Chicken Biryani",
  "team": "TEAM_ID",
  "channel": "CHANNEL_ID",
  "channel_type": "channel"
}
```

The workflow configuration uses the Slack Trigger with the `message` event.

---

# 🛡️ 3. IF Node — Prevent Bot Loops

### Node

```text
If
```

This is an important part of the architecture.

When the automation posts the AI-generated answer back to Slack, that response can itself generate another Slack message event.

Without filtering, the workflow could potentially process its own response again.

The workflow therefore checks:

```javascript
{{ !$json.bot_id }}
```

The condition allows messages that **do not contain `bot_id`** to continue through the AI processing path.

### Concept

```text
Slack Message
      │
      ▼
 Does message contain bot_id?
      │
 ┌────┴────┐
 │         │
 YES       NO
 │         │
Stop     Process
          │
          ▼
       AI Chain
```

This is a simple but important **loop-prevention mechanism** for Slack-based automations.

# 📝 4. Edit Fields — Extract Recipe Name

### Node

```text
Edit Fields
```

The Slack event contains the message text inside the Slack `blocks` structure.

The workflow extracts:

```javascript
{{ $json.blocks[0].elements[0].elements[0].text }}
```

and stores it as:

```text
blocks[0].elements[0].elements[0].text
```

This extraction is configured in the Edit Fields node.

For example:

```text
Slack Event
    ↓
blocks
    ↓
elements
    ↓
rich_text_section
    ↓
text
    ↓
Chicken Biryani
```

# 🧠 5. Basic LLM Chain

### Node

```text
Basic LLM Chain
```

The extracted recipe name is passed to the LLM using the following prompt concept:

```text
List all the products and ingredients needed to make <recipe>.

Return a clear bulleted list with approximate quantities.

Keep it short and practical.

If the recipe name is unclear, ask the user to rephrase it.
```

The actual workflow prompt dynamically injects the extracted Slack message into the LLM request.

For example:

```text
User Input:
Chicken Biryani
```

becomes conceptually:

```text
List all the products and ingredients needed to make Chicken Biryani.
Return a clear bulleted list with approximate quantities.
Keep it short and practical.
```

# 🤖 6. OpenAI Chat Model

### Node

```text
OpenAI Chat Model
```

The Basic LLM Chain is connected to an OpenAI Chat Model.

The workflow currently specifies:

```text

```

The model connection is configured through the OpenAI credential attached to the workflow.

Architecture:

```text

                    │
                    │ AI Model
                    ▼

                    │
                    ▼
```

# 💻 7. JavaScript Response Processing

### Node

```text
Code in JavaScript
```

After the LLM generates the response, the workflow processes the result using JavaScript.

The current implementation retrieves the LLM's `text` field and removes unnecessary leading/trailing whitespace:

```javascript
const llmOutput = $json.text?.trim();

return [
  {
    json: {
      output: llmOutput
    }
  }
];
```

This creates a clean output structure:

```json
{
  "output": "Here’s a practical list of products and ingredients..."
}
```

The JavaScript implementation is present in the workflow JSON.

# 💬 8. Send AI Response to Slack

### Node

```text
Send a message
```

The cleaned output from the JavaScript node is passed to Slack using:

```javascript
{{ $json.output }}
```

The message is posted back to the configured Slack channel.

Final flow:

```text
LLM Response
     ↓
JavaScript
     ↓
output
     ↓
Slack Message
```

# 🔄 Loop Prevention

One of the most important implementation details is avoiding an infinite Slack → n8n → Slack → n8n loop.

Without filtering:

```text
User Message
    ↓
n8n
    ↓
AI Response
    ↓
Slack
    ↓
Slack Trigger
    ↓
n8n
    ↓
AI Response
    ↓
Slack
    ↓
...
```

The IF node checks whether:

```javascript
$json.bot_id
```

exists.

The workflow continues only when:

```javascript
!$json.bot_id
```

is true.

This prevents the bot's own messages from entering the AI processing path.

# 📊 Architecture Characteristics

## Event Driven

The workflow does not require polling Slack repeatedly.

Instead:

```text
Slack Event
     ↓
Webhook
     ↓
n8n
```

This provides a reactive automation model.

---

## AI Powered

The recipe request is interpreted and processed by an LLM rather than relying on hardcoded recipe rules.

This means the same workflow can handle many different inputs:

```text
Chicken Biryani
Curd Rice
Paneer Butter Masala
Vegetable Fried Rice
Masala Dosa
Chicken Curry
```

---

## Dynamic Prompting

The user's Slack message becomes part of the LLM prompt:

```javascript
{{ $json.blocks[0].elements[0].elements[0].text }}
```

This allows the workflow to dynamically process different user requests.

---

## Lightweight Post Processing

JavaScript is used after the LLM instead of adding another AI node.

```text
LLM
 ↓
JavaScript
 ↓
Clean Output
```

This keeps the workflow simple and makes deterministic formatting separate from AI generation.

# 📌 Project Summary

**n8n Slack AI Recipe Assistant** demonstrates a practical implementation of an **event-driven Generative AI automation pipeline**.

The solution connects:

```text
Slack
  +
n8n
  +
OpenAI
  +
JavaScript
```

to transform a simple Slack message into an AI-generated, practical response.

The workflow uses Slack events as the trigger, conditional logic to prevent bot loops, field extraction to isolate the user's request, an LLM chain for intelligent processing, JavaScript for deterministic response cleanup, and Slack for delivering the final result. The workflow's node connections implement this sequence directly.
